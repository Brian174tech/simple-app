GUIDES / CORE PRINCIPLES
THE FOUNDATION

Core principles.

A small set of durable ideas can guide hundreds of implementation decisions. Use them as defaults, not as a substitute for context.

01

Least privilege

Give each identity the minimum permissions required, for only as long as needed. Separate duties and review access as responsibilities change.

IN PRACTICE A reporting service can read its own data, but cannot change account settings or access unrelated records.
LIMIT ACCESS
02

Fail securely

When a dependency, check, or service fails, the system should land in a safe state. Make denial the default when authorization cannot be verified.

IN PRACTICE If an access-control service is unavailable, protected actions are paused rather than allowed through.
SAFE DEFAULTS
03

Defense in depth

Use independent layers of protection. No single control is perfect; multiple controls make a failure harder to exploit and easier to contain.

IN PRACTICE Combine authentication, authorization, input validation, and monitoring instead of relying on one perimeter.
LAYER DEFENSE
04

Minimize attack surface

Every exposed endpoint, feature, permission, and dependency adds complexity. Remove what is not needed and keep what remains well maintained.

IN PRACTICE Disable unused interfaces and remove demo accounts before a service is deployed.
REDUCE EXPOSURE
05

Keep it simple

Simple security rules are easier to inspect, test, and get right. Prefer clear, consistent mechanisms over clever exceptions and duplicated checks.

IN PRACTICE Use one well-understood authorization layer consistently across routes.
CLARITY WINS
